8 Datatyper

Tjänstedomänens meddelanden bygger på den XML-schemarepresentation av EN13606-1 (CEN/ISO 13606, Electronic Healthcare Record Communication) som finns i domänschemat ehr_patientsummary_1.0.xsd, och på ISO 21090-datatyperna i ISO_dt.xsd. TKB:n beskriver inte typerna utan hänvisar till NPÖ:s informationsspecifikation och meddelandestrukturer (se 2.2 EHR-extrakt). Avsnittet är genererat ur schemat.

ISO 21090-datatyper i de logiska modellerna

I de logiska modellerna har ISO 21090-datatyperna ersatts med närmaste FHIR-datatyp:

ISO 21090 FHIR
II Identifier
CD, CE, CV CodeableConcept
CS code
ST string
TS dateTime
IVL_TS Period
BL boolean
INT integer
ED Attachment
AD Address
TEL ContactPoint
EN, PN HumanName
ANY string (polymorft värde, se ELEMENT)

Abstrakta typer

RECORD_COMPONENT, CONTENT, ITEM och IDENTIFIED_ENTITY är abstrakta. I ett meddelande anges den konkreta typen med xsi:type (till exempel SECTION eller ENTRY för CONTENT, CLUSTER eller ELEMENT för ITEM). I de logiska modellerna finns subtypernas egna element i en valfri grupp per subtyp. Rekursiva strukturer (SECTION.members, CLUSTER.parts, FOLDER.sub_folders) utvecklas inte ett andra varv.

Domänschema ehr_patientsummary_1.0.xsd (namnrymd urn:riv:ehr:patientsummary:1).

Any attestations for a Record Component. The proof field should be a cryptographic hash of the RECORD_COMPONENT it attests, but it is recognised that in many implementations the components will change to point to new components that revise them. In that case, the proof should sign the unchanging parts of the component only.
